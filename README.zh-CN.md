# 长夜幻境 Web（EvernightRealm Web）

> 长夜幻境的客户端界面——用浏览器或桌面客户端，走进属于你小圈子的私密世界。

[English](./README.md) · [简体中文](./README.zh-CN.md) · [繁體中文（台灣）](./README.zh-TW.md) · [日本語](./README.ja-JP.md)

## 这是什么？

这是长夜幻境的客户端。长夜幻境是一个自主部署、离线优先的平台，面向小规模玩家群体。活动、角色、资产与聊天都在这里呈现——全部在局域网内完成，不需要公网、云账号或遥测。

## 功能规划（开发中）

- **活动视图**：跟随场景、阶段与事件的发展
- **角色面板**：玩家、NPC 与管理员的身份，共处一个私密世界
- **资产管理**：查看与交易虚拟物品，归属可审计
- **私密聊天**：消息只留在你自己的服务器上
- **离线优先**：客户端完全对接你的本地服务器，不依赖云服务

## 当前状态

正在积极开发中，尚未发布稳定版本。

## 发布后的使用方式（规划）

- 在同一局域网内用浏览器打开主机地址即可加入，无需安装
- 也将提供 Windows、macOS、Linux 桌面客户端
- 无需第三方注册；数据只保存在主机上

## 界面语言

简体中文、繁体中文（台湾）、English、日本語。界面语言默认跟随系统语言，可在服务器入口页切换并记住选择；系统语言不在支持列表时回退 English。

## 服务器连通性检查

服务器入口页提供“服务器连通性检查”：向你的服务器读取健康与时间端点，显示服务名与版本、服务器的 UTC 时间、按服务器显示时区换算后的当地时间，以及本次请求的识别码。检查失败时界面只说明失败原因（无法连接、没有回应、服务尚未就绪等）并给出错误码与请求识别码，不会留下任何看起来像成功的数据；所有数值都来自服务器，不使用本机时钟或示例数据。

## Root 初始化引导

全新的服务器还没有 Root，入口页因此有一张只读的“Root 初始化检查”卡片：它向服务器查询初始化状态，并如实显示五种结论之一——尚未初始化、已完成初始化、连不上服务器、服务器拒绝回报、这一次结果不明确（还没保存地址时则先说明没有地址，不发出任何请求）。只有服务器明确回答“还没有 Root”时，卡片才列出接下来要在服务器那台机器上做的事：停止服务、必要时先建立结构、执行 `evernight-server init-root --password-stdin`、重新启动服务、回到本页再查一次。查询失败不会被说成任何一种状态；“重新检查”只是再问一次，全是只读请求，不会建立、更换或覆盖任何凭据。

这张卡片不收集口令：卡内没有任何密码输入框，也不把任何凭据发往服务器——初始化 Root 只有在服务器本机上执行命令这一条路。配置文件里已有凭据之后，卡片不再列出步骤，只说明初始化已完成；登录入口就在下方“登录与会话”卡片里，本卡自身依旧只读，不收集任何口令。

## 登录与身份恢复

服务器完成初始化后，入口页的“登录与会话”卡片就是进入应用的通道：

- 登录页先显示这次要登录的是哪一台服务器（生效地址，若探测过还带服务名与版本），再让你交凭据。两条通路：Root 登录（只有口令）与账户登录（登录名加口令）；账户通路复用服务器已有的登录接口，本应用不提供自助注册；唯一的建号入口是 Root 在 Root 控制台里使用的那一个。
- 每种失败各说自己那一句：口令被拒是统一的一句（服务器不区分“查无此人”与“口令不对”，界面也无从分开）、被限流说稍后再试、连不上和本机存储失败各归各。任何提示都不会回显你输入的口令，也不转述服务器原文；口令不保存在本机，也不自动填入。
- 登录成功后的身份以服务器的回答为准，不是表单上选了什么；受保护页面一律先过会话检查，服务器回答之前不会闪现任何受保护内容。被退回登录页时保住的“返回目标”只认本应用已登记的合法路径，其他目标（包括外部网址）一律回到入口页。
- 应用重开时会先恢复并验证上一次会话：验证中只给中性提示；仍有效就在会话卡列出经服务器确认的主体、设备标识与到期时间（UTC）；已被判定失效就退回登录并清除本机保存的会话凭据。
- 已登录态的“登录与会话”卡片上有“登出”按钮：让服务器撤销这一次绑定的会话——浏览器路径收到同名同属性的 Cookie 删除指令、原生路径清掉这台服务器在系统级安全存储里的那份凭据；重复按登出是幂等的，不会产生新会话也不叫用户重新登录。连不上时本机照样清理，提示把“本机已清理”与“服务器撤销未确认”分开讲，不会谎称已在服务器登出，也不暗示所有设备已下线。
- 已登录态的卡片上另有“我的设备”入口：按服务器回答列出你自己的会话、标出你正在用的这一台，并可撤销另一台。范围由服务端限定在你自己的主体内，面板无法指名别人的设备；撤销当前这台等同于在它上面登出。列表已过期、会话早已失效、连不上服务器三种情况各说各的，没发生的撤销不会被说成成功。
- 已登录态的卡片上另有“更改密码”入口：改密要求在请求中当场交出当前密码作再认证——“还登录着”从来不是改密的授权；改密成功按服务器策略让名下全部会话（含这台设备）退出，界面进入退出态并提示用新密码重新登录。密码不落地任何本地缓存：三个输入栏只存在于对话框中、用完即清且全部遮蔽。带有“首次登录必须改密”标记的账号，服务端只放行改密、登出与当前会话查询，其余受保护功能一律返回专用机器码 2010；卡片据此只留这两个入口，不呈现注定被拒绝的按钮。
- Root 控制台今天接通了七项能力：开设服务器管理员、浏览管理员目录、查看与编辑单笔资料、停用与恢复管理员登录、重置管理员登录凭据、软删除管理员，以及服务器的账户创建策略。开设表单交出去的是三个值——登录名、显示名称与一次性初始口令——请求里没有角色或主体类别的格子，因为“建的是管理员”由端点决定。初始口令不再回显、不写入任何本地缓存，界面任何一处都不会出现它；新建账号首次登录必须把它换掉，换掉之前服务器本来就挡住其余受保护入口（专用机器码 2010）。重置凭据走的是同一套做法：Root 在一个遮罩输入框里键入替换口令，送出即清空，界面从不回读，确认对话框在请求发出之前讲清这次重置会做什么。目录是真正的分页视图而不是定长短清单：翻页与总数由服务器回显、只有一种状态筛选（已删除的也列出来）、按授予时刻由新到旧排序，而配置 Root 按设计永远不会成为其中一条可编辑的行。点开一行会先按标识从服务器重读这笔单条资料，编辑表单才出现；表单只改显示名，并且连同所见过的现值一起提交——对着过期画面的保存会被拒绝（2013）且什么都不覆盖。停用要先经确认对话框：点名目标、讲清影响（新登录被拒、其名下现有会话全部撤销）与不会发生的事——这不是删除。恢复只恢复重新登录的能力：停用时撤销的会话不会复活，尚未完成的首次改密要求仍然有效。删除是另一条终态通路，也自带确认对话框：点名账户，在送出之前讲清后果——登录停止、现有会话撤销、没有恢复入口。停用与删除是两种状态，所以恢复登录永远不会让已删除账户复生，界面上也不会有那样的按钮。已删除的记录转为只读：显示服务器写入的占位显示名与删除时刻，并说明历史操作背后的身份仍然可解析，因为授予、会话与审计仍指向同一个账户。配置的 Root 凭据不是目录里的一行，因此在这里永远不构成删除目标。这个界面上不存在“停用 Root”或“管理员停用其他管理员”的提交路径；对着过期依据或重复的状态变更会被 2014 拒绝，界面给的是“重新读取再看”，不是再点一次按钮；对已删除的账户发起编辑、重置凭据或再次删除都会被 2015 拒绝，而任何删除在结果不明时都不会自动补发。界面显示的每一个数字与标签都来自服务端响应，不做乐观填充。第七项是一张策略卡：它现读三个值（管理员可否创建普通账户、自注册模式、可否创建访客账户），保存之前必经确认对话框。画面把两件事分开讲——保存下来的是这个部署的意图，而三条创建通路都还没有实现，因此“未登录的浏览器现在能看到什么”那一列照样是关闭；模式只给 closed 与 open 两个选项，approval／invite 这类名字就算被直接送出去，后端也会以 2016 拒绝，界面据此另成一句，而不是念成 1004 那句“格式不对”。读不到时卡片不显示任何猜测值，写入失败时三个值都回到上一份服务器真相，结果不明时不会自动补发。
- Root 管理模块的其余部分仍在开发：已登录的主页只呈现真实身份与此刻真正可用的入口，不会用示例数据冒充。身份那一行按服务器回传的 `roles` 显示，管理员看到的是“服务器管理员”，没有授予的账户看不到；管理员自己打开同一张表单，只会收到“没有权限”那一句（机器码 2011），重新登录也不会让它变成可用。原生客户端的会话凭据保存在系统级安全存储，浏览器路径由 HttpOnly Cookie 代管，绝不明文落盘。浏览器路径那枚 Cookie 只在页面确实经 HTTPS 提供时才标 Secure；区域网明文 HTTP 部署下，浏览器的防线由 SameSite 加服务器的来源判定承担，要用 HTTPS 就得在服务器前面自行加一层终结 TLS 的反向代理。

## 服务器地址

服务器入口页可以直接输入要使用的服务器地址并保存在本机，切换测试服务器不再需要重新构建。只接受完整的 `http://` 或 `https://` 地址（不得包含用户名或密码），并且必须连得通才会保存：格式不合格时按具体原因提示（例如“地址需要以 http:// 或 https:// 开头”）并且完全不发出请求；格式合格但连不通时不保存，并说明原因而不是假装成功。界面把“当前使用的地址”和“本机已保存的地址”分开列出，并说明当前值从何而来；调试构建下编译期参数 `--dart-define=ER_SERVER_BASE_URL` 优先，此时界面会明确告知本机保存的地址尚未生效。你输入的内容只保存在自己的设备上。

## 界面出错时

如果应用某一部分无法正常显示，界面会切换到一个安全的提示页面：说明问题发生的位置（界面绘制、后台任务或与服务器往来）、一个用于对照本机日志的诊断码，以及服务器请求的关联 ID（如果与请求有关）。你可以按“返回可用页面”回到可使用的界面。提示页面不会显示错误原文、程序堆栈或服务器地址，也不会把任何内容发送到外部——问题只记录在你自己的设备上。

需要说明的是：刚刚出错的那一块在返回后可能短暂留白，要等界面下一次重建才会恢复；如果同样的问题反复出现，提示页面会建议你重新载入应用。

## 从源码构建

各平台图标与启动画面是生成的、不纳入版本控制：它们由 `assets/icons/` 下的四张来源图推导。全新克隆的仓库在构建前先执行

    python tools/icons/generate_icons.py

缺少图标资源时 Android、iOS、macOS 与 Windows 构建会直接失败，Web 构建则会没有图标。`python tools/icons/generate_icons.py --check` 只核对现状，不写入任何文件；详见 `tools/icons/README.md`。
