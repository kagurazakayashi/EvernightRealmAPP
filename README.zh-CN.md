# 长夜幻境 Web（EvernightRealm Web）

> 长夜幻境的客户端界面——用浏览器或桌面客户端，走进属于你小圈子的私密世界。

[English](./README.md) · [简体中文](./README.zh-CN.md) · [繁體中文（台灣）](./README.zh-TW.md) · [日本語](./README.ja-JP.md)

## 这是什么？

这是长夜幻境的客户端。长夜幻境是一个自主部署、离线优先的平台，面向小规模玩家群体。活动、角色、资产与聊天都在这里呈现——全部在局域网内完成，不需要公网、云账号或遥测。

## 功能规划（开发中）

- **活动视图**：跟随场景、阶段与事件的发展
- **角色面板**：玩家、NPC 与管理员的身份，共处一个私密世界
- **资产管理**：查看与交易虚拟物品，归属可审计
- **私密聊天**：消息只留在你自己的服务器上
- **离线优先**：客户端完全对接你的本地服务器，不依赖云服务

## 当前状态

正在积极开发中，尚未发布稳定版本。

## 发布后的使用方式（规划）

- 在同一局域网内用浏览器打开主机地址即可加入，无需安装
- 也将提供 Windows、macOS、Linux 桌面客户端
- 无需第三方注册；数据只保存在主机上

## 界面语言

简体中文、繁体中文（台湾）、English、日本語。界面语言默认跟随系统语言，可在服务器入口页切换并记住选择；系统语言不在支持列表时回退 English。

## 服务器连通性检查

服务器入口页提供“服务器连通性检查”：向你的服务器读取健康与时间端点，显示服务名与版本、服务器的 UTC 时间、按服务器显示时区换算后的当地时间，以及本次请求的识别码。检查失败时界面只说明失败原因（无法连接、没有回应、服务尚未就绪等）并给出错误码与请求识别码，不会留下任何看起来像成功的数据；所有数值都来自服务器，不使用本机时钟或示例数据。

## Root 初始化引导

全新的服务器还没有 Root，入口页因此有一张只读的“Root 初始化检查”卡片：它向服务器查询初始化状态，并如实显示五种结论之一——尚未初始化、已完成初始化、连不上服务器、服务器拒绝回报、这一次结果不明确（还没保存地址时则先说明没有地址，不发出任何请求）。只有服务器明确回答“还没有 Root”时，卡片才列出接下来要在服务器那台机器上做的事：停止服务、必要时先建立结构、执行 `evernight-server init-root --password-stdin`、重新启动服务、回到本页再查一次。查询失败不会被说成任何一种状态；“重新检查”只是再问一次，全是只读请求，不会建立、更换或覆盖任何凭据。

这张卡片不收集口令：卡内没有任何密码输入框，也不把任何凭据发往服务器——初始化 Root 只有在服务器本机上执行命令这一条路。配置文件里已有凭据之后，卡片不再列出步骤，只说明初始化已完成；登录入口就在下方“登录与会话”卡片里，本卡自身依旧只读，不收集任何口令。

## 登录与身份恢复

服务器完成初始化后，入口页的“登录与会话”卡片就是进入应用的通道：

- 登录页先显示这次要登录的是哪一台服务器（生效地址，若探测过还带服务名与版本），再让你交凭据。两条通路：Root 登录（只有口令）与账户登录（登录名加口令）；账户通路复用服务器已有的登录接口。账号只从三个入口产生：Root 在 Root 控制台开设管理员，管理员在管理员端创建普通账户（以服务器的账户创建策略开放那条通路为前提），以及策略开放时自助注册画面上匿名提交的那一个——它本身从不替任何人登录。自助注册现在三种模式都已上线：开放、审批、以及邀请码模式（注册画面读服务器的 `invite_code_required`，只在邀请码模式下显出邀请码字段，再把码交给同一条 `POST /auth/register`，由它核销成一个普通账户）。访客进入现已提供，而且是它被限制的那条样子：服务器入口层上另有一张卡读服务器的 `guest_open`，只有你主动按下它那颗按钮才会建立这个临时身份——页面加载、刷新与重连都不会写任何东西。
- 每种失败各说自己那一句：口令被拒是统一的一句（服务器不区分“查无此人”与“口令不对”，界面也无从分开）、被限流说稍后再试、连不上和本机存储失败各归各。任何提示都不会回显你输入的口令，也不转述服务器原文；口令不保存在本机，也不自动填入。
- 登录成功后的身份以服务器的回答为准，不是表单上选了什么；受保护页面一律先过会话检查，服务器回答之前不会闪现任何受保护内容。被退回登录页时保住的“返回目标”只认本应用已登记的合法路径，其他目标（包括外部网址）一律回到入口页。
- 应用重开时会先恢复并验证上一次会话：验证中只给中性提示；仍有效就在会话卡列出经服务器确认的主体、设备标识与到期时间（UTC）；已被判定失效就退回登录并清除本机保存的会话凭据。
- 已登录态的“登录与会话”卡片上有“登出”按钮：让服务器撤销这一次绑定的会话——浏览器路径收到同名同属性的 Cookie 删除指令、原生路径清掉这台服务器在系统级安全存储里的那份凭据；重复按登出是幂等的，不会产生新会话也不叫用户重新登录。连不上时本机照样清理，提示把“本机已清理”与“服务器撤销未确认”分开讲，不会谎称已在服务器登出，也不暗示所有设备已下线。
- 已登录态的卡片上另有“我的设备”入口：按服务器回答列出你自己的会话、标出你正在用的这一台，并可撤销另一台。范围由服务端限定在你自己的主体内，面板无法指名别人的设备；撤销当前这台等同于在它上面登出。列表已过期、会话早已失效、连不上服务器三种情况各说各的，没发生的撤销不会被说成成功。
- 已登录态的卡片上另有“更改密码”入口：改密要求在请求中当场交出当前密码作再认证——“还登录着”从来不是改密的授权；改密成功按服务器策略让名下全部会话（含这台设备）退出，界面进入退出态并提示用新密码重新登录。密码不落地任何本地缓存：三个输入栏只存在于对话框中、用完即清且全部遮蔽。带有“首次登录必须改密”标记的账号，服务端只放行改密、登出与当前会话查询，其余受保护功能一律返回专用机器码 2010；卡片据此只留这两个入口，不呈现注定被拒绝的按钮。
- 自助注册画面是给还站在门外的人的。它只在服务器的匿名入口能力（`sign_up_open`）说这条路开着时才出现在入口页，而且收登录名、显示名与本人自选的口令三个字段，外加一个只由服务器第三个布尔（`invite_code_required`）在邀请码模式下才显出的邀请码字段。邀请码是短暂停留的秘密：它只填在一个输入框、只随这一次请求本体发送，不进地址栏、浏览器历史、日志或任何缓存，成功时连同其余字段一起清空。整个画面上没有任何角色、账户类型或审批状态的控件：建出来的是哪一类主体由端点决定，不由表单决定，多带这类栏位的请求在写库之前就被服务器拒掉。露出这扇门从来不是准入的保证：服务器在自己那笔写入事务里重读策略，所以 Root 中途翻回去的开关没法靠一张旧画面走过去，被藏起来的邀请码字段也绕不过“邀请码模式要带码”那道写入检查。
- 提交之后剩下什么，取决于服务器跑的是哪种模式，而画面只转述它拿到的回答。`open` 时得到一个立刻能用刚选的口令登录的账户，摘要就这么说。`approval` 时同样三个字段交出的是一份申请：账户存在、登录名被占用、口令已保存——但在有人批准之前它不能登录。画面这时如实写“申请已提交，尚未获准登录”，也不摆一个它知道必然失败的登录出口。`invite` 时一枚有效码在建号同一笔交易内核销，落成一个立刻能用刚选口令登录的普通账户——摘要与开放模式读起来一模一样，因为登录行为本就相同；换不出账户的码（缺失、形状不合、已撤销、已过期、用尽、或并发下被抢先用掉）以一句不泄露细节的 2023 拒绝，刻意不说差的是哪一半。匿名入口刻意一直不说模式名字，所以这件事由服务器的写入回答，不由界面猜。
- 申请人可以在另一个画面上问自己的申请怎么样了，而那不是一次登录。它每次查询都重新验证凭据（登录名与口令放在 POST 本体里，绝不进 URL），只回答结局——还在等、已批准、已拒绝——加上提交时刻，以及已有决定时的决定时刻。它不签发会话、也不保存任何东西：不下 Cookie、不留令牌，刷新或离开都不会剩下可被复用的东西；没有排队位次、没有审核人、没有理由文本，那些属于服务器自己的事。在这里查到已批准的人会被导向一般登录页；这条通路不会让任何账户提早可用。
- 用同一个登录名重复提交会得到与其他人一样的唯一性回答——申请会继续占用那个名字，被拒绝的申请也一样。所以被拒绝的人不能拿同一个名字再来一次，别人也拿不走。之后切换服务器的模式不会改变已经交上来的任何一份申请：策略开关既不替谁放行，也不丢任何一份历史；那需要一个明确的决定，而决定是在管理员端的注册申请画面上做出的。

- 服务器入口层上另有一张卡是访客那扇门。它只在服务器的匿名 `guest_open` 说这条路开着时才出现；而与注册画面不同（注册从不替任何人登录），按下这张卡的按钮会同时建立这个临时身份并交回一枚会话：`POST /auth/guest` 的 Cookie 与登录走同一条分发通路，所以浏览器把它交给 HttpOnly Cookie 代管，原生端写入平台的安全存储。昵称栏是可选的，而且只是展示信息——留空时由服务器给出它自己的临时编号，这一点在送出之前就先讲清楚。这张卡也把自己的限制写在前面：这个身份不属于任何活动，不携带任何服务器级授予（管理端与 Root 端对他回 2011），也没有口令可改——所以已登入的卡片对访客不摆“变更密码”那一颗，只给装置管理、轮换与登出这些真的能用的入口——而会话到期、主动登出、换设备或清掉本机凭据之后，这一趟就结束了。这里刻意没有“凭昵称找回”那一屏：一个你能打出来的名字不是凭据，这个账户之后怎么处理，是管理员在普通账户目录里核实这个人之后由他决定。页面加载、刷新、重连与一次失败的重新检查都不会创建任何东西——只有那一颗按钮会，而它在进行中连点只发一趟请求。进去之后落到玩家面，那里如实写着这个身份还不属于任何活动；而身份那一行读的是服务器自己的 `account_type`，显示成“访客（临时身份）”，所以刷新或重开之后说的话仍然对得上。

- Root 控制台今天接通了八项能力：开设服务器管理员、浏览管理员目录、查看与编辑单笔资料、停用与恢复管理员登录、重置管理员登录凭据、软删除管理员、服务器的账户创建策略，以及管理服务器注册邀请码。第八项这张卡分页列出 Root 签发的邀请码，可按状态（有效／已过期／已用满／已撤销）与标签筛选，每行只显示元数据——标签、派生状态、已核销次数与上限、签发／到期／（被撤销时）撤销时刻——绝不显示码本身。签发必经确认框，之后在一个可选中的一次性展示格里给出完整邀请码：界面不自动复制、不放分享钮、不画二维码，所以丢了只能重新签发而非读回（服务器只存它的哈希）。撤销点名该码、说明它只挡住之后的核销、是单向的、不是删除；重复撤销拿到 2022 并只给一个重读出口。这张卡只管凭证——签发、名册与撤销——它自己不核销任何码：核销是注册画面那一侧的事（门外的人拿自己的码走 `POST /auth/register`），把策略切成 invite 则是另一张策略卡单独的决定。这道分工是刻意的，不是一条缺失的通路——Root 在这里签出的码，一旦策略设成 invite，就能在注册画面上被核销。开设表单交出去的是三个值——登录名、显示名称与一次性初始口令——请求里没有角色或主体类别的格子，因为“建的是管理员”由端点决定。初始口令不再回显、不写入任何本地缓存，界面任何一处都不会出现它；新建账号首次登录必须把它换掉，换掉之前服务器本来就挡住其余受保护入口（专用机器码 2010）。重置凭据走的是同一套做法：Root 在一个遮罩输入框里键入替换口令，送出即清空，界面从不回读，确认对话框在请求发出之前讲清这次重置会做什么。目录是真正的分页视图而不是定长短清单：翻页与总数由服务器回显、只有一种状态筛选（已删除的也列出来）、按授予时刻由新到旧排序，而配置 Root 按设计永远不会成为其中一条可编辑的行。点开一行会先按标识从服务器重读这笔单条资料，编辑表单才出现；表单只改显示名，并且连同所见过的现值一起提交——对着过期画面的保存会被拒绝（2013）且什么都不覆盖。停用要先经确认对话框：点名目标、讲清影响（新登录被拒、其名下现有会话全部撤销）与不会发生的事——这不是删除。恢复只恢复重新登录的能力：停用时撤销的会话不会复活，尚未完成的首次改密要求仍然有效。删除是另一条终态通路，也自带确认对话框：点名账户，在送出之前讲清后果——登录停止、现有会话撤销、没有恢复入口。停用与删除是两种状态，所以恢复登录永远不会让已删除账户复生，界面上也不会有那样的按钮。已删除的记录转为只读：显示服务器写入的占位显示名与删除时刻，并说明历史操作背后的身份仍然可解析，因为授予、会话与审计仍指向同一个账户。配置的 Root 凭据不是目录里的一行，因此在这里永远不构成删除目标。这个界面上不存在“停用 Root”或“管理员停用其他管理员”的提交路径；对着过期依据或重复的状态变更会被 2014 拒绝，界面给的是“重新读取再看”，不是再点一次按钮；对已删除的账户发起编辑、重置凭据或再次删除都会被 2015 拒绝，而任何删除在结果不明时都不会自动补发。界面显示的每一个数字与标签都来自服务端响应，不做乐观填充。第七项是一张策略卡：它现读三个值（管理员可否创建普通账户、自注册模式、可否创建访客账户），保存之前必经确认对话框。画面把两件事分开讲——保存下来的是这个部署的意图，而「管理员创建普通账户」「自助注册」「邀请码」与「访客进入」这四条通路现在都已存在，所以每一列都如实跟着那个开关走，不再有一条是因为背后没实现而永远关闭；模式给 closed、open、approval 与 invite 四个选项，approval 收下的是在批准之前不能登录的申请，卡上如实说出批准的含义（审批在管理员端的注册申请画面上进行，那里任何决定都发不出服务器级角色）；invite 只让持有效码者自行注册，卡上也说明这枚码按账户逐次核销、发不出任何服务器级角色、换出的账户与开放模式一样可立即登录。这张卡还给不出的模式（未来多出的名字）会照服务器原字显示、不悄悄改名，而列在这里的选项必须与后端真的接受的那些同步：清单少一个能写的模式，保存另外两栏时就会把服务器记录的模式顶掉。读不到时卡片不显示任何猜测值，写入失败时三个值都回到上一份服务器真相，结果不明时不会自动补发。
- 管理员端今天接线了八项能力：创建普通账户、翻阅普通账户目录、读取与维护单笔基础资料、停用与恢复普通账户的登录、重置普通账户的登录凭据、批准或拒绝一份注册申请，以及把访客账户就地升级为正式账户，还有为访客运行只读的绑定预检（它从不绑定任何人）。表单交出三个值——登录名、显示名与一次性初始口令——没有角色、账户类型或活动的字段，因为“新建的是普通账户”由端点决定：不带任何服务器级授予，也没有任何活动档案或资产。开关开没开不做预读：服务器在建立事务的同一份快照上现读策略，关着时回机器码 2017（与 2011 那句“没有权限”是分开的两句话，Root 走这条端点也一样被挡），名字被占用回 2012，成功卡会明说账号已创建但还不属于任何活动。初始口令不再显示、不存在任何状态里、也不出现在界面任何一处；新账号首次登录必须改密，受与所有账号相同的服务器端闸门（2010）约束。
- 普通账户目录今天可以翻阅与维护：分页目录按状态（全部／启用／已停用）、来源（全部／普通账户／访客账户）与名称关键字（比对登录名与显示名两栏）筛选，翻页与总数一律取服务器回显；点一行会先按标识从服务器重读这笔单笔资料，编辑表单才出现。这本目录列不到管理员，也列不到 Root——持有服务器级授予的人归 Root 的管理员目录，两本目录彼此互斥；没有管理权的会话读它只会拿到「没有权限」（2011）而不是一个空清单，匿名则是 2002。表单只改显示名，并且连同所见过的现值一起提交——对着过期画面的保存会被拒绝（2013）且什么都不覆盖，界面给的是「重新读取这份资料」，不是再点一次保存；登录名不在这里修改，凭据、权限与安全状态也不在这张表单上（本体里多带任何隐藏字段都会被服务器打成 1004）。单笔详情没有活动、资产与消息这三块：那些模块尚未实现，界面不拿空列表或 0 冒充查得到的真相。标识格式不对、账户不存在、他是管理员、他已被删除，四种输入都收到同一个 1001，这个端点因此不是「某人是不是管理员」的探针。
- 普通账户的登录停用与恢复接在同一张单笔详情卡上，界面前先说清范围：这里动的是这个账户在这台服务器上的登录能力，不是某一场活动里的玩家限制——停用会拒绝他今后的登录，并撤销他在每台设备上的现有会话。提交之前必经确认对话框，它点名目标、讲完影响范围与「这不是删除」；取消时一个请求都不发。按钮只由服务器读回的现状决定（启用中只给停用、已停用只给恢复、认不出的值只说一句话，不猜方向），依据值取上一次从服务器读到的现状，因此对着过期画面的保存会被 2014 拒绝且什么都没发生，界面给的是「重新读取这份资料」，不是再点一次按钮。成功后界面把状态、停用时刻与「这次让几个会话退出」全部换成服务器回应，并重新读取目录；恢复只恢复重新登录的能力——停用期间被撤销的会话不会复活，还没完成的首次改密仍然被 2010 挡着，已被删除的账户更不能这样恢复。访客账户走同一组控件，因为这本目录的定义就是「不持有服务器级授予」。活动内的禁言、交易冻结与阵营限制不在这里，也没有被伪装成可用。
- 普通账户的凭据重置接在同一张单笔详情卡的第三条白名单上：`PUT /admin/accounts/{account_id}/password`，请求本体只有 password 一栏，而且刻意没有依据值——操作者拿不出「现行哈希」这类诚实的锚点，所以对着不明的结果再按一次那颗按钮不是重试，而是又做一次完整的重置（再撤一轮可能新签发的会话、再留一笔审计）；界面因此从不自动补发。交付沿用 Root 那侧已批准的方案：口令由管理员亲自交、服务器不生成也不回显、不设默认口令，输入框遮蔽、在请求发出前就清空，成功句只讲这次让几个会话退出与「线下交付、首次登录必须改密」，那串字之后不再出现在界面任何一处，也不进日志、审计、可读偏好或自动复制的剪贴板。停用中的目标照样可以重置（重置不是解除停用），界面不按状态分岔；重置不动停用、不动删除终态，也不会免掉他欠的那次改密——今天没有账户级审批状态，「待审批」如实就是「欠首次改密」，重置写的是「必须改」而不是「不用改」。访客账户在这条通路上出局：他本来没有一般密码，替他写一个进去等于把他的身份升级成普通账户，那该走同一张卡上的访客升级区；界面据此不摆那颗按钮、只说这一句，服务器也以机器码 2018 回答同一句话。权限不足（2011）、目标不在这本目录（1001）与口令不合规（1004）各说各话；界面上的每一个数字与状态都来自服务端响应，不做乐观填充。
- 访客的就地升级接在同一张详情卡的第四条白名单上，只有服务端读回的来源字段说他是访客时才会出现。`PUT /admin/accounts/{account_id}/upgrade` 的本体只有正式登录名与一次性口令两栏，没有账户类型、角色、状态或旗标的格子：升级出来的形态恒为「仍欠首次改密的普通账户」，由端点决定而不是由请求决定，界面上连「升成管理员」都写不出来。发送之前，卡片把两处分野讲清：这是就地转正，保留同一个账户标识、显示名与全部历史记录——不是新建账户再把访客删掉，也不是把他绑到另一个既有正式账户（那条执行通路今天还不存在，界面能给的只有只读预检，见下一条）；确认对话框唸出目标与新的正式登录名。口令与重置同规：遮蔽栏、在请求发出前清空、不回显、结果不明绝不自动补发。成功句的撤销数量取自服务端响应：升级在同一笔交易里撤销旧访客凭据名下的全部会话——这是本步批准的决定，捡到手旧临时令牌的人不会静默变成正式账户——回到门内的唯一方式是用新凭据真实登录一次，而首次登录立刻被要求先改密的闸门（2010）挡下。成功后界面跟着服务端回的记录走：访客控件收起、凭据区如实出现、目录重读。停用中的访客不给升级钮，只给「先恢复他的登录」那一句；目标已转正或此刻被停用回 2024，名字被占用回 2012 而访客那一行一个字都不改；访客本人来敲这条端点拿到的是 2011——这条只有管理员走得通的路，存在的意义之一就是答不了他。
- 访客绑定预检以只读预览的形式接在同一张详情卡上：`POST /admin/accounts/{account_id}/bind-preflight` 的本体只有目标账户标识一格，一次只评估「这个访客 × 这个目标」的一对——不存在替访客罗列可绑定目标的读法，这张画面不是寻人工具。它纯只读、零写入：不改账户、不撤会话、不动授予，也不写一笔审计；结果面板第一句显著标明「这只是预检结果：尚未绑定」。服务端回来的是 200 预览而不是错误：不可绑定时以稳定原因记号逐条点名——同源自同一对、来源已转正或已退休、来源停用中、来源带着服务器级授予（形态缺陷方向）、目标也是访客、目标停用中，以及预检尚未接入的账户引用（一旦出现，一切绑定整体被阻止，直到对应模块接入；未接入的表名只进服务器日志）。回应还带出该访客名下有多少会话会在执行时登出、这份预检按哪一版数据库运行，以及恒为 target_self_initiated 的同意形态：将来绑定也只能由目标账户持有人以自己的已认证会话发起，管理端永远拿不到代他人完成绑定的按钮，而那条执行通路今日不存在。来源或目标不在目录收敛成与详情同句的 1001，访客本人拿 2011，目标标识缺失或坏形拿 1004 点名栏位——这一步不发布任何新机器码。
- 注册申请在管理员端有自己的一页。`GET /admin/registrations` 列的是还在等的与已经被拒绝的：每一行只有登录名、显示名、状态、提交时刻，以及已有决定时的决定时刻，没有别的。这就是审核需要的全部事实；页面上没有凭据、没有会话材料、也没有角色栏，而普通账户目录仍是另一本书、有自己的范围条件。两颗按钮只在服务端回传的确实是 `pending` 时出现；已被拒绝的那一行改为一句实话——决定在这里是单向的，没有任何通路能重开，而那个登录名继续被占用。两颗按钮旁边都没有理由输入框：内部备注与可公开理由都不落库，界面摆一个填了会被悄悄丢掉的格子只会更糟。确认对话框点名目标，并说清落下什么（一个能用自己选的口令登录、不带任何服务器级角色的普通账户）与不会发生什么（不替他签发会话、不解除任何停用、不改名也不删除）。成功句取自 PUT 响应——落地的是哪个决定、是谁的申请——随后重读名册而不是本地改那一行，因为被批准的人已经不在这本书上。2021 说这份申请已有决定：界面只给重读这一个出口，结果不明时绝不把决定再发一次。1001 说目标根本不在这本名册，2011 说这个会话不能对任何人做决定——三种处置各自成句。这一页不做任何通知：这台服务器没有通知模块，申请人只能重新出示自己的凭据，在状态查询那页看到结局。

- Root 管理模块的其余部分仍在开发：已登录的主页只呈现真实身份与此刻真正可用的入口，不会用示例数据冒充。身份那一行按服务器回传的 `roles` 显示，管理员看到的是“服务器管理员”，没有授予的账户看不到；管理员自己打开同一张表单，只会收到“没有权限”那一句（机器码 2011），重新登录也不会让它变成可用。原生客户端的会话凭据保存在系统级安全存储，浏览器路径由 HttpOnly Cookie 代管，绝不明文落盘。浏览器路径那枚 Cookie 只在页面确实经 HTTPS 提供时才标 Secure；区域网明文 HTTP 部署下，浏览器的防线由 SameSite 加服务器的来源判定承担，要用 HTTPS 就得在服务器前面自行加一层终结 TLS 的反向代理。

## 服务器地址

服务器入口页可以直接输入要使用的服务器地址并保存在本机，切换测试服务器不再需要重新构建。只接受完整的 `http://` 或 `https://` 地址（不得包含用户名或密码），并且必须连得通才会保存：格式不合格时按具体原因提示（例如“地址需要以 http:// 或 https:// 开头”）并且完全不发出请求；格式合格但连不通时不保存，并说明原因而不是假装成功。界面把“当前使用的地址”和“本机已保存的地址”分开列出，并说明当前值从何而来；调试构建下编译期参数 `--dart-define=ER_SERVER_BASE_URL` 优先，此时界面会明确告知本机保存的地址尚未生效。你输入的内容只保存在自己的设备上。

## 界面出错时

如果应用某一部分无法正常显示，界面会切换到一个安全的提示页面：说明问题发生的位置（界面绘制、后台任务或与服务器往来）、一个用于对照本机日志的诊断码，以及服务器请求的关联 ID（如果与请求有关）。你可以按“返回可用页面”回到可使用的界面。提示页面不会显示错误原文、程序堆栈或服务器地址，也不会把任何内容发送到外部——问题只记录在你自己的设备上。

需要说明的是：刚刚出错的那一块在返回后可能短暂留白，要等界面下一次重建才会恢复；如果同样的问题反复出现，提示页面会建议你重新载入应用。

## 从源码构建

各平台图标与启动画面是生成的、不纳入版本控制：它们由 `assets/icons/` 下的四张来源图推导。全新克隆的仓库在构建前先执行

    python tools/icons/generate_icons.py

缺少图标资源时 Android、iOS、macOS 与 Windows 构建会直接失败，Web 构建则会没有图标。`python tools/icons/generate_icons.py --check` 只核对现状，不写入任何文件；详见 `tools/icons/README.md`。
